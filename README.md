# Spotter

Spotter is a member-facing web application built for a 400-member gym. It gives members instant access to answers grounded strictly in the gym's verified records, self-service check-in with a daily 4-digit code, personal attendance and ledger tracking, automated membership renewal via Paystack, and seamless WhatsApp handoff to the on-duty front desk officer.

---

## Core Features (MVP)

- **F-1 Ask About the Gym:** Grounded shared answers retrieved from approved cards filtered by the member's effective tier (`BASIC` or `PREMIUM`). Every generated answer passes a deterministic grounding verification to prevent hallucinated figures or dates.
- **F-2 My Records:** Immediate private answers for a member's own attendance, subscription expiry date, and outstanding balance. Queries use direct parameterized SQL filtered strictly by authenticated member ID and logged to `PrivateAccessLog` (never chunked or embedded in vector storage).
- **F-3 Daily Check-in:** In-gym check-in using a rotating 4-digit daily code. Enforces gym operating hours, limits attendance to once per calendar day, and gates members past their grace period.
- **F-4 Pay & Renew:** Self-service subscription renewals and arrears settlements processed through Paystack. Extends membership dates automatically within the verified webhook database transaction with no staff intervention required.
- **F-5 Ask the Desk:** Automated fallback for out-of-scope or ungrounded questions. Identifies the front desk officer currently on duty and opens WhatsApp with the question pre-typed.

---

## Tech Stack

- **Framework:** Next.js (App Router), React 18, TypeScript
- **Styling:** Vanilla CSS powered by custom design tokens (`tokens.json` &rarr; `tokens.css`)
- **Database:** PostgreSQL with `pgvector` extension
- **ORM & Data Access:** Prisma Client for relational models, raw SQL (`$executeRaw` / `$queryRaw`) for vector search and CardChunk indexing
- **AI & Retrieval:** Google Gemini API (`gemini-2.5-flash` for classification and answer synthesis, `text-embedding-004` 768-dim embeddings for vector search)
- **Payments:** Paystack (webhook transaction signature verification)

---

## Architecture & Safety Guarantees

1. **Deterministic Rules Layer:** `src/server/router/rules.ts` evaluates questions for medical topics, other members' data, door access, monetary decisions, and staff conduct *before* making any model or retrieval call. Pattern hits refuse cleanly with no LLM cost.
2. **Strict Data Separation:** 
   - Shared cards are embedded, indexed, and retrieved by tier.
   - Private member records are queried by session member ID with zero vector search.
3. **Digit-Level Grounding Verification:** Answers generated by the LLM undergo strict digit matching. If any number sequence in the answer cannot be found in the source card chunk or question, the response is discarded (`BLOCKED_UNGROUNDED`) and handed off to the desk.
4. **Minimum Record Threshold (FR-11b):** The app refuses shared Q&A automatically if fewer than 30 approved cards exist in the database.

## Getting Started

### Prerequisites

- **Node.js** (v18.17+ or v20+)
- **PostgreSQL** instance with the `vector` extension enabled
- **Google Gemini API Key**
- **Paystack API Keys** (test keys for development)

### 1. Clone & Install

```bash
git clone <repository-url>
cd Spotter
npm install
```

### 2. Configure Environment Variables

Copy the example environment file and fill in the required credentials:

```bash
cp .env.example .env.local
```

| Variable | Description |
| :--- | :--- |
| `DATABASE_URL` | Neon pooled connection string (`pgbouncer=true&connection_limit=1`) |
| `DIRECT_URL` | Neon direct, unpooled connection string (used for migrations) |
| `TEST_DATABASE_URL` | Isolated database instance for test suite |
| `GEMINI_API_KEY` | Google Gemini API key |
| `PAYSTACK_SECRET_KEY` | Paystack secret key |
| `PAYSTACK_PUBLIC_KEY` | Paystack public key |
| `SESSION_SECRET` | 32+ character random secret for signed session cookies |
| `NODE_ENV` | `development` or `production` |

### 3. Compile Design Tokens

Compile `tokens.json` to `tokens.css`:

```bash
npm run tokens
```

### 4. Database Setup & Seeding

Run Prisma migrations and generate the client:

```bash
npx prisma migrate dev
npx prisma generate
```

Seed initial records (1 gym, 1 owner, 1 desk officer, sample BASIC/PREMIUM members, and membership plans):

```bash
npm run seed
```

### 5. Start the Development Server

```bash
npm run dev
```

Open [http://localhost:3000](http://localhost:3000) with your browser to view the application.
